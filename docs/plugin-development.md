# MWEF Plugin Development Guidelines (Schema v1)

**English** | [简体中文](plugin-development_CN.md)

This document defines the MWEF 0.3.x plugin package format. Examples generated by this project use `VlHash` as the author.

## 1. Package Format

A release must be a gzip-compressed tar archive with a `.tar.gz` or `.tgz` extension and a maximum size of 8 MiB. `mwef-plugin.json` must be located at the archive root:

```text
mwef-plugin.json
overlay/
  luci/
    controller/
    view/
  www/
i18n/
  zh-CN.json
  en.json
scripts/
```

Every directory is optional; only `mwef-plugin.json` is required. The package must not contain absolute paths, `..` path segments, backslash-separated paths, symbolic links, hardware devices, FIFOs, or sockets.

## 2. Manifest

Minimal manifest:

```json
{
  "schemaVersion": 1,
  "id": "hello-mwef",
  "name": {
    "zh-CN": "Hello MWEF",
    "en": "Hello MWEF"
  },
  "version": "1.0.0",
  "author": "VlHash",
  "license": "MIT",
  "mwef": ">=0.2.0",
  "permissions": []
}
```

Field rules:

- `schemaVersion`: currently fixed at `1`.
- `id`: must match `^[a-z][a-z0-9_-]{0,47}$`; the installation directory, grant record, and static namespace all use this value.
- `name`, `description`: either strings or objects containing `zh-CN` and `en` values.
- `version`: SemVer is recommended; maximum length is 32 characters.
- `author`: the author or organization; content generated by this project uses `VlHash`.
- `mwef`: declares the minimum compatible framework version.
- `permissions`: may contain only identifiers from the permission table below.
- `navigation`: optional menu contribution containing a localized `label`, a LuCI `route` array, and an `order` value.
- `entrypoints`: identifies Web and API entry points for review tools.
- `hooks`: optional shell-script declarations; scripts must be under `scripts/` and are never executed automatically in a way that bypasses the permission system.

See the [plugin manifest JSON Schema](../schema/mwef-plugin.schema.json) for the complete constraints.

## 3. Overlay Mapping

- `overlay/luci/` is merged into the generated layer for `/usr/lib/lua/luci/`.
- `overlay/www/` is merged into the generated layer for `/www/`.
- `i18n/` is published at `/xqext/plugins/<id>/i18n/`.

A plugin may write only within its own namespace. It must not overwrite MWEF core controllers, `web/inc/header.htm`, files belonging to another plugin, or system authentication and login logic. Controllers must continue using the LuCI `;stok=...` session and must not expose a separate unauthenticated listener.

## 4. Navigation

```json
"navigation": {
  "label": { "zh-CN": "示例插件", "en": "Example Plugin" },
  "route": ["web", "xqext", "hello_mwef"],
  "order": 100
}
```

After the plugin is enabled, MWEF generates its secondary menu entry under Extensions from the manifest. No modification of the core `nav.htm` is required.

## 5. Localization Files

A plugin should provide at least `i18n/zh-CN.json` and `i18n/en.json`. Translation keys must remain stable, and new keys must not change the meaning of existing keys. A page may read the framework configuration and load:

```text
/xqext/plugins/<id>/i18n/<language>.json
```

Never insert user input directly into `innerHTML`; use `textContent` or escaped LuCI output.

## 6. Permissions

| Permission | Purpose |
| --- | --- |
| `system.read` | Read system and hardware status |
| `filesystem.read` | Read files within the declared scope |
| `filesystem.write` | Write to plugin or declared data directories |
| `network.client` | Initiate external network requests |
| `service.control` | Control declared system services |
| `shell.execute` | Execute shell scripts declared by the plugin |

Requested permissions are shown before installation. A plugin must not use permissions that have not been granted. In particular, Lua controllers run with the router Web service's privileges, so reviewers should treat undeclared filesystem, network, service, or shell behavior as a violation.

## 7. Xiaomi WebUI Style

- Use the native `bc.css`, `layout.css`, and `/xqext/core.css` stylesheets.
- Use `#bd.xqext-page` for the main content and follow the 1040 px content width, 60 px horizontal padding, and white rounded panel conventions.
- Use title dividers, two-column label/control rows, and the native blue confirmation button for settings.
- Use blue header dividers for lists; clearly label dangerous operations and require confirmation.
- Use a grey title bar, backdrop, and Cancel/Confirm controls for dialogs.
- Do not override the native blue `body` background.

## 8. Build and Validate

```powershell
./tools/build-plugin.ps1 -Source examples/hello-mwef
```

Before release, validate JSON, JavaScript syntax, Lua syntax, shell syntax, archive paths, and both Chinese and English localization files.

## 9. Online Distribution

Plugins intended for the official online catalog must also comply with the [Online Plugin Index Specification](plugin-index.md). Publishing metadata never bypasses package validation, checksum verification, or administrator permission confirmation.
